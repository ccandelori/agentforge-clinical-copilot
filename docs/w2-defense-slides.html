Defense map

Five load-bearing decisions

  1. Scanned intake forms persist as QuestionnaireResponse — not as silent updates to demographics, allergies, meds. The agent suggests; the clinician promotes.
  2. Lab facts persist via procedure_*, not via FHIR Observation create. procedure_result.document_id ties the row back to the PDF.
  3. LangGraph wiring is completed in W2, not introduced. The Planner already ships standalone (DEVIATIONS 2026-05-02).
  4. PHI containment narrows three boundaries — the model provider is the load-bearing exception.
  5. The eval gate is the deliverable. Boolean rubric, 50 cases, PR-blocking, with a self-test that proves it bites.

Each gets a slide. Each names the alternative we rejected and why.

4 / 18
Decision 1 of 5

Intake forms → QuestionnaireResponse

The agent surfaces suggestions with citations. Promotion to the chart is a separate, human action.

Alternative considered

Write extracted demographics, meds, allergies, family history straight to patient_data / the medication list / the allergies list.

Why we chose otherwise

OCR is fallible. "Penicillin V" misread becomes a charted allergy. A misaligned column becomes a false medication. The chart is updated by humans, not by VLM extraction.

Tradeoff: The clinician has to confirm. Promotion-write-back UI is post-W2.

W2_ARCHITECTURE.md §2.3 invariant I-2 · enforced at the Pydantic boundary, the persistence-test layer, and as an eval-suite rubric item.

Decision 2 of 5

Lab facts → procedure_* tables

Write through the system of record. Let FHIR resources materialize as a reader concern.

Alternative considered

Write through FhirObservationService or the FHIR REST surface.

Why we chose otherwise

Tool-pattern principle (DEVIATIONS 2026-05-02 / 2026-05-01): AgentForge writes through JWT-validated internal endpoints, not FHIR REST. FHIR REST would mean provisioning a second auth surface (OAuth2 client credentials + token mgmt) for the same trust boundary.

procedure_result.document_id = documents.id — schema-level linkage to the uploaded PDF. The FHIR cross-link (Observation.derivedFrom, DiagnosticReport.presentedForm) needs transformer changes this fork doesn't make. Not promised as a W2 deliverable.

W2_ARCHITECTURE.md §2.3 invariant I-1.

Decision 5 of 5

The eval gate is the deliverable

The agent's behavior changes weekly. The gate's behavior is the contract with graders.

50-case golden set

  • Extraction (12) — values, units, ranges, intake fields
  • Evidence retrieval (10) — guideline chunks, ablation pairs
  • Citations (10) — every claim cited; bbox in page
  • Refusals (8) — unsafe action, prompt injection
  • Missing data (10) — agent acknowledges, doesn't fabricate

Boolean rubric, five categories

  • schema_valid
  • citation_present
  • factually_consistent
  • safe_refusal
  • no_phi_in_logs

Threshold: any category drops >5% from baseline OR below 90% pass rate → CI fails.

Two layers, orthogonal failure modes: programmatic grounding (W1, deterministic) + LLM-as-judge (NEW W2, claude-sonnet-4-6, temperature=0, boolean per category).

The contract

One Pydantic class makes the rest verifiable

class Citation(BaseModel):
    source_type: SourceType    # LAB_PDF | INTAKE_FORM | GUIDELINE | OPENEMR_RECORD
    source_id: str
    page_or_section: str
    field_or_chunk_id: str
    quote_or_value: str
    page_bbox: PageBBox | None  # required for LAB_PDF / INTAKE_FORM

    @model_validator(mode="after")
    def _scanned_sources_require_high_confidence_bbox(self):
        # rejects LAB_PDF / INTAKE_FORM citations whose
        # page_bbox is missing or whose bbox_confidence < 0.7
  • Type-level distinction between patient-record facts and guideline evidence — UI renders them in different sections; rubric checks a guideline citation never supports a patient-specific claim.
  • Bbox confidence is the anti-hallucination floor. A low-confidence field can only land in unsupported_fields — never as a structured value.
  • Same contract end-to-end: extraction → retrieval → verifier → UI overlay.

Hybrid RAG

BM25 + dense + rerank, behind an interface

Corpus

~30 docs in sidecar/data/guidelines/: ADA diabetes, JNC 8 / ACC-AHA hypertension, AHA/ACC lipids, CKD staging, common-lab interpretive notes. ~600 chunks of ~500 tokens. Fits in memory.

Why hybrid

BM25 catches term-overlap (rare lab abbrevs, brand names). Dense catches paraphrase. RRF gets both into the rerank pool.

Packaging

Embedding + reranker pre-baked into the sidecar Docker image — no ~370MB cold-start download. Eval suite includes a passthrough-vs-rerank ablation pair.

14 / 18
Eval gate

How we know the gate bites

Three places it runs

  • Local prek — 10-case smoke subset, fast feedback per commit
  • GitLab CI (.gitlab-ci.yml, NEW) — full 50, authoritative PR-blocker per the spec
  • GitHub Actions mirror — same script, same config, can't drift

Gate self-test

test_gate_blocks_regression.py monkey-patches intake-extractor to return one fabricated lab value, runs the full 50, and asserts factually_consistent drops >5% — i.e., the build would fail.

Separate CI job; runnable manually. Graders can trigger it directly.

We do not seed the 50-case golden set with intentionally-broken cases. Mixing pass and fail expectations into one dataset makes the rubric ambiguous.

Q&A primer

Anticipated questions

Q: How do you know the gate catches the regression graders will introduce?

A separate test that monkey-patches the extractor to fabricate a value and asserts the rubric fires. Run it directly to confirm.

Q: Why not write extracted intake fields straight to the proper tables?

OCR mistakes become charted clinical state. The chart is updated by humans, not by VLM extraction.

Q: Why introduce LangGraph in W2?

It's already pinned; the Planner already ships standalone. We're closing a documented deferral, not adopting a new framework.

Q: What if the VLM hallucinates a bounding box?

Pydantic validator rejects scanned-source citations with bbox_confidence < 0.7. Low-confidence → unsupported_fields, never a structured value.

Q: How is PHI contained in extraction prompts?

Prompt-body redaction at the LangfuseClient adapter — not at call sites. Logs latency, model, tokens, validation result. no_phi_in_logs rubric inspects exports for synthetic-PHI patterns.

Q: Why default to a local reranker instead of Cohere?

Cost predictability, no API key in CI, spec accepts "or equivalent." Cohere is a one-env-var swap if eval scores demand it.
