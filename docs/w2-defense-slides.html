Defense map

Five load-bearing decisions

  1. Scanned intake forms persist as QuestionnaireResponse — not as silent updates to demographics, allergies, meds. The agent suggests; the clinician promotes.
  2. Lab facts persist via procedure_*, not via FHIR Observation create. procedure_result.document_id ties the row back to the PDF.
  3. LangGraph wiring is completed in W2, not introduced. The Planner already ships standalone (DEVIATIONS 2026-05-02).
  4. PHI containment narrows three boundaries — the model provider is the load-bearing exception.
  5. The eval gate is the deliverable. Boolean rubric, 50 cases, PR-blocking, with a self-test that proves it bites.

Each gets a slide. Each names the alternative we rejected and why.

Decision 1 of 5

Intake forms → QuestionnaireResponse

The agent surfaces suggestions with citations. Promotion to the chart is a separate, human action.

Alternative considered

Write extracted demographics, meds, allergies, family history straight to patient_data / the medication list / the allergies list.

Why we chose otherwise

OCR is fallible. "Penicillin V" misread becomes a charted allergy. A misaligned column becomes a false medication. The chart is updated by humans, not by VLM extraction.

Tradeoff: The clinician has to confirm. Promotion-write-back UI is post-W2.
P2.1 punch-list correction: the writer routes through OpenEMR's QuestionnaireResponseService::saveQuestionnaireResponse() (via an IntakeQuestionnaireResponsePersister seam), not a raw INSERT. EVENT_PRE_SAVE / EVENT_POST_SAVE fire; audit user is wired; FHIR canonical reference resolves (P4#4 logical id agentforge-intake-form).

W2_ARCHITECTURE.md §2.3 invariant I-2 · enforced at the Pydantic boundary, the persistence-test layer, and as an eval-suite rubric item.

Decision 2 of 5

Lab facts → procedure_* tables

Write through the system of record. Let FHIR resources materialize as a reader concern.

Alternative considered

Write through FhirObservationService or the FHIR REST surface.

Why we chose otherwise

Tool-pattern principle (DEVIATIONS 2026-05-02 / 2026-05-01): AgentForge writes through JWT-validated internal endpoints, not FHIR REST. FHIR REST would mean provisioning a second auth surface (OAuth2 client credentials + token mgmt) for the same trust boundary.

procedure_result.document_id = documents.id — schema-level linkage to the uploaded PDF. The FHIR cross-link (Observation.derivedFrom, DiagnosticReport.presentedForm) needs transformer changes this fork doesn't make. Not promised as a W2 deliverable.
P2.2 punch-list correction: InternalLabPersistController parses raw payloads into a final readonly LabValue domain primitive at the boundary. Non-empty testName + value enforced at construction; bad rows yield HTTP 400 (no PHI echoed) instead of silent empty-string corruption.

W2_ARCHITECTURE.md §2.3 invariant I-1 · CLAUDE.md "parse, don't validate."

Decision 4 of 5

PHI containment — three boundaries

"PHI never leaves the sidecar" would be dishonest. Here's the truth.

Boundary Auth What crosses What doesn't
Browser ↔ OpenEMR PHP Session + CSRF PDF upload, PDF preview for the overlay Sidecar isn't on this boundary
OpenEMR PHP ↔ Sidecar Signed JWT document_id, extracted facts, persistence calls PDF bytes — held in sidecar memory only; not persisted, not logged
Sidecar ↔ Anthropic HTTPS, BAA Rendered page images for vision Same BAA W1 already takes for chart-text reasoning
Honest framing: Cloud Claude vision is a real production dependency. Demo data is synthetic. The LLM-client abstraction is the swap point for on-prem vLLM in production hardening — W1's deferred work.

Doc-upload pipeline · what shipped

Browser to chart in one round trip

A clinician drops a PDF in the AgentForge drawer, types "extract this." The pipeline lands the extraction in OpenEMR before the synthesis reply hits the screen.

Step Surface What happens
1 Vue dashboard drawer useUploadAttachment composable wraps the file as a PendingAttachment with doc_type inferred client-side (P4#1).
2 BFF + JWT-authed PHP endpoint BFF mints a session-bound JWT; InternalUploadDocumentController validates it, runs the upload through OpenEMR's Document::createDocument(), audits, returns document_id.
3 Sidecar / Haiku vision Supervisor routes to intake-extractor; VisionExtractor calls Haiku with strict-schema Pydantic and emits per-field bboxes. Telemetry: record_extraction_call Langfuse spans on success + failure (P2.3).
4 Option A persist (sidecar-initiated) Orchestrator._maybe_persist_extraction POSTs back to /agentforge/internal/persist_intake with a fresh JWT. Persister routes through QuestionnaireResponseService (events fire, audit user wired).
5 Dashboard ExtractionPanel AgentTurnResponse carries extraction + persisted_resource_id + structured citations. Panel renders below chat bubble; "View source (N)" button visible.
Why Option A (sidecar-initiated) over Option B (dashboard-driven): single round trip from the dashboard's POV; sidecar already holds the document_id + extraction in hand; the user's first turn already lands the QR cascade. The confirm-panel later moves data from "extracted but unapproved" to structured tables — never from "in-memory" to "stored."

Trust artifact · bbox overlay

"View source" is the citation analogue for vision

Every extracted field carries a page_bbox. The DocumentViewer modal turns those rectangles into a visible "show your work" property.

End-to-end

  • Click "View source (18)" on the ExtractionPanel.
  • Modal opens; InternalDocumentBytesController serves the PDF (Cache-Control: max-age=300, private).
  • pdf.js renders pages 1..N at canvas-true coordinates.
  • Each Citation.page_bbox becomes a blue rectangle overlay positioned in the page coordinate system.

Why it's load-bearing

  • The Pydantic Citation validator already rejects scanned-source citations with bbox_confidence < 0.7. Any value the panel surfaces has a verifiable bbox.
  • The clinician can confirm visually before promotion. The chart write is still a separate human action (Decision 1).
  • Same contract end-to-end: extraction emits Citation, persistence stores it, UI consumes it.
Honest caveat: Haiku-vision bboxes land in the right region but can be offset by a row/cell on dense forms. Acceptable trust artifact, not pixel-tight. PNG intake forms (Reyes, Kowalski) won't render — pdf.js can't parse image/png bytes — so the demo runbook sticks to typed PDFs (Chen, Whitaker).

Decision 5 of 5

The eval gate is the deliverable

The agent's behavior changes weekly. The gate's behavior is the contract with graders.

50-case golden set

  • Extraction (12) — values, units, ranges, intake fields
  • Evidence retrieval (10) — guideline chunks, ablation pairs
  • Citations (10) — every claim cited; bbox in page
  • Refusals (8) — unsafe action, prompt injection
  • Missing data (10) — agent acknowledges, doesn't fabricate

Boolean rubric, five categories

  • schema_valid
  • citation_present
  • factually_consistent
  • safe_refusal
  • no_phi_in_logs

Threshold: any category drops >5% from baseline OR below 90% pass rate → CI fails.

Two layers, orthogonal failure modes: programmatic grounding (W1, deterministic) + LLM-as-judge (NEW W2, claude-sonnet-4-6, temperature=0, boolean per category).

The contract

One Pydantic class makes the rest verifiable

class Citation(BaseModel):
    source_type: SourceType    # LAB_PDF | INTAKE_FORM | GUIDELINE | OPENEMR_RECORD
    source_id: str
    page_or_section: str
    field_or_chunk_id: str
    quote_or_value: str
    page_bbox: PageBBox | None  # required for LAB_PDF / INTAKE_FORM

    @model_validator(mode="after")
    def _scanned_sources_require_high_confidence_bbox(self):
        # rejects LAB_PDF / INTAKE_FORM citations whose
        # page_bbox is missing or whose bbox_confidence < 0.7
  • Type-level distinction between patient-record facts and guideline evidence — UI renders them in different sections; rubric checks a guideline citation never supports a patient-specific claim.
  • Bbox confidence is the anti-hallucination floor. A low-confidence field can only land in unsupported_fields — never as a structured value.
  • Same contract end-to-end: extraction → retrieval → verifier → UI overlay (slide 13).

Hybrid RAG

BM25 + dense + rerank, behind an interface

Corpus

~30 docs in sidecar/data/guidelines/: ADA diabetes, JNC 8 / ACC-AHA hypertension, AHA/ACC lipids, CKD staging, common-lab interpretive notes. ~600 chunks of ~500 tokens. Fits in memory.

Why hybrid

BM25 catches term-overlap (rare lab abbrevs, brand names). Dense catches paraphrase. RRF gets both into the rerank pool.

Packaging

Embedding + reranker pre-baked into the sidecar Docker image. Honest sizing: as-shipped delta is ~1.2 GB (not the spec's ~370 MB — bge-reranker-base fp32 weights are 1.1 GB). Cohere remains the network-gated alternative.

Eval gate · how we know the gate bites

The self-test is a safety property, not a regression check

A separate test deliberately regresses the supervisor adapter and asserts the gate fails. The gate isn't just a CI rate-of-change check — it's an empirical correctness claim about the gate itself.

50-case W2 suite

  • extraction (12) · evidence_retrieval (10) · citations (10) · refusal (8) · missing_data (10)
  • YAML cases under sidecar/tests/eval/cases/week2/, real fixtures under week2/example-documents/ (Chen, Whitaker, Reyes, Kowalski).
  • 10-case smoke subset tagged eval_smoke — pre-commit hook in <30s with mocked supervisor + judge.

Two-stage harness

  • Programmatic (deterministic): schema_valid, citation_present, no_phi_in_logs.
  • LLM-as-judge: factually_consistent, safe_refusal at temperature=0; retry-with-fresh-seed + tiebreaker on disagreement.
  • Either layer failing fails the case.
Self-test (Task 19): test_gate_blocks_regression.py wires a regressed supervisor that emits "A1c = 15.5%" with the citation deliberately stripped. The citations pass rate drops 1.0 → 0.6 — outside the 5% regression band and below the 0.9 floor. The gate must return verdict.passed is False. Same path through the CLI exits non-zero. Three end-to-end tests under @pytest.mark.gate_validation; runnable by graders directly.

Why citation-strip and not numeric mismatch: the W2 harness's _JUDGE_BY_CATEGORY only routes HALLUCINATION/REFUSAL to the LLM judge; the W2 yaml suite uses five different categories. The programmatic citation_present grader carries the load-bearing assertion. Extending judge routing for value-fabrication is a documented follow-up.

Production-grade discipline

Persistence-layer correctness, in three slices

These are not bug fixes — they're the three places the persistence story has to be airtight before "ship it" is honest.

P2.1 · Service routing

IntakeQuestionnaireResponseWriter previously did a raw INSERT against an injected DBAL connection. That bypassed ServiceSaveEvent::EVENT_PRE_SAVE / EVENT_POST_SAVE, the audit-user wire-up, and the generated narrative HTML.

Now routes through QuestionnaireResponseService::saveQuestionnaireResponse() via an IntakeQuestionnaireResponsePersister interface seam. Production binding wraps the legacy service; the interface keeps the writer unit-testable in the isolated harness (BaseService drags ADODB file-include side effects).

P2.2 · LabValue domain primitive

InternalLabPersistController previously validated only the array shape and forwarded a normalized list<array<string, mixed>> to the writer, which silently substituted empty strings for missing or non-string fields — procedure_result rows with blank result_text.

final readonly LabValue primitive enforces non-empty testName + value at construction. The controller parses-not-validates at the boundary; \DomainException becomes HTTP 400 with no PHI echoed back. CLAUDE.md's "parse, don't validate" applied at the wire.

P4#4 · Logical id (FHIR canonical)

QuestionnaireResponse.questionnaire_id was being persisted as NULL, breaking the FHIR canonical reference (Questionnaire/{id}) on every overlay-UI round-trip. Display-name shadowing made the row non-resolvable.

New IntakeQuestionnaireLookup + SeededIntakeQuestionnaire DTO + stable kebab-case logical id agentforge-intake-form threaded through writer + persister. Two Doctrine migrations: seed update + production backfill.

The headline isn't "we fixed three bugs." It's that the persistence layer is the point where AI-suggested data crosses into the system of record — boundary parsing, service-event participation, and FHIR-canonical resolvability are the three things that have to be true before any defense of "the chart is updated by humans" holds.

UX decisions · placement + opt-in

Two surface decisions worth defending

P4#3 · Panel yank · placement won

What changed: The original W1 per-chart AgentForge panel (Twig + JS bundle + turn.php/upload_document.php entry points + Bootstrap event subscriber + tests) was deleted in one atomic commit.

Why: The 2026-05-06 placement-design grilling concluded the per-chart embed was "dangerously wrong" — a top-level co-pilot drawer in the new dashboard is the correct placement. From that decision onward, the legacy panel was deprecated but still wired in. A 2026-05-08 review surfaced latent bugs (lab PDFs hard-coded to intake schema; unfinished citation-overlay plumbing). Two paths: fix the bugs or delete the surface.

What we learned: Once a placement decision is made, the deprecated surface is carrying cost — both maintenance (PHPStan/PHPCS keep seeing it) and review attention. Deleting deprecated surfaces immediately, the same day the placement flips, would have saved that round-trip.

P4#2 · "Ask guidelines" toggle

The straight-line fix for "the dashboard guideline RAG is unreachable" was "forward req.message as evidence_query on every turn." That mis-routes every chart-Q&A turn through the W2 evidence retriever — pays the RAG round-trip and emits guideline citations even when the clinician didn't ask.

What shipped: An "Ask guidelines" toggle in the composer toolbar (next to attach), backed by agentforge.guidelineMode, default off. When on, the store mirrors the user's text into both message and evidence_query; when off, neither field is sent and the W1 chart-Q&A loop runs as before.

Why visible affordance over heuristic intent classification: "summarize last visit" should not trigger guideline RAG. Auto-detect from message text ("guideline", "according to") is too brittle — false positives turn chart-Q&A into RAG; false negatives strand the feature. The user can demo "watch me toggle Guidelines and ask a clinical question" without the audience guessing what triggered the route.

Q&A primer

Anticipated questions

Q: How do you know the gate catches the regression graders will introduce?

test_gate_blocks_regression.py wires a regressed adapter that emits a fabricated A1c with the citation deliberately stripped. citations pass rate drops 1.0 → 0.6; gate returns verdict.passed is False. CLI exits non-zero. Runnable directly.

Q: Why not write extracted intake fields straight to the proper tables?

OCR mistakes become charted clinical state. The chart is updated by humans, not by VLM extraction.

Q: Why introduce LangGraph in W2?

It's already pinned; the Planner already ships standalone. We're closing a documented deferral, not adopting a new framework.

Q: What if the VLM hallucinates a bounding box?

Pydantic validator rejects scanned-source citations with bbox_confidence < 0.7. Low-confidence → unsupported_fields, never a structured value.

Q: How is PHI contained in extraction prompts?

Prompt-body redaction at the LangfuseClient adapter — not at call sites. Logs latency, model, tokens, validation result. no_phi_in_logs rubric inspects exports for synthetic-PHI patterns.

Q: Why default to a local reranker instead of Cohere?

Cost predictability, no API key in CI, spec accepts "or equivalent." Cohere is a one-env-var swap if eval scores demand it.

Q: Why was the original per-chart panel deleted?

Placement decision flipped on 2026-05-06 to a top-level dashboard drawer. The legacy panel had latent bugs (lab PDFs hard-coded to intake schema, unfinished overlay plumbing) and no demo path used it — fixing dead code is pure carrying cost. See slide 20.

Q: Why is the eval baseline a stub at 1.0?

The production SupervisorAdapter bridge ships (sidecar/src/agentforge/eval/supervisor_adapter.py); the regen CLI's real-LLM branch is a deliberate manual-edit seam so the test surface stays token-free. The gate's self-test proves the gate bites; replacing the stub with a measured baseline is a once-per-meaningful-change run on the droplet.
